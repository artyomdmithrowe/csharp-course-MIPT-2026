# Financial Accounting App

Консольное приложение для модуля «Учет финансов».

Файл с требованиями: [Требования.pdf](./Requirements.pdf)

## Структура проекта

```text
src/FinancialAccountingApp
  Infrastructure
    DependencyInjection
    Repositories
  Interfaces
  Models
    Bank
    Category
    Enums
    Ids
    Operation
  Services
    Facades
    Factories
  Program.cs
  FinancialAccountingApp.csproj
```

## Что реализовано

В проекте реализованы основные сущности модуля финансового учета:

- `BankAccount` — банковский счет
- `Category` — категория доходов и расходов
- `Operation` — финансовая операция

Для этих сущностей реализованы основные сценарии:

- создание
- получение по `Id`
- получение списка всех сущностей
- обновление через методы доменных моделей и фасады
- удаление

Для основных сущностей модуля (`BankAccount`, `Category`, `Operation`) реализована базовая CRUD-функциональность.

Реализованные пользовательские сценарии:

- создание счета
- создание категории
- создание операции
- изменение баланса счета при создании доходной или расходной операции
- переименование счета
- переименование категории
- изменение описания операции
- получение операций по счету
- получение операций по категории
- получение операций за период

## Основные идеи решения

Архитектура разделена на несколько уровней ответственности:

- `Models` — доменные сущности и их инварианты
- `Interfaces` — абстракции репозиториев и сервисов
- `Services/Factories` — создание доменных объектов
- `Services/Facades` — пользовательские сценарии
- `Infrastructure/Repositories` — хранение данных
- `Infrastructure/DependencyInjection` — регистрация зависимостей

### Доменные сущности

#### BankAccount

Содержит:

- `Id`
- `Name`
- `Balance`

Ограничения:

- имя счета не может быть пустым
- баланс не может быть отрицательным
- изменение баланса выполняется только через методы модели

#### Category

Содержит:

- `Id`
- `Type`
- `Name`

Ограничения:

- имя категории не может быть пустым
- тип категории фиксируется при создании

#### Operation

Содержит:

- `Id`
- `Type`
- `BankAccountId`
- `CategoryId`
- `Amount`
- `Date`
- `Description`

Ограничения:

- сумма операции должна быть больше нуля
- описание может отсутствовать

## Где применены принципы SOLID

### Single Responsibility Principle

- `BankAccount`, `Category`, `Operation` отвечают только за свое состояние и доменные ограничения.
- Репозитории отвечают только за хранение и получение сущностей.
- Фабрики отвечают только за создание сущностей.
- Фасады отвечают только за пользовательские сценарии.

### Open/Closed Principle

- Проект можно расширять добавлением новых сервисов, аналитики, импорта и экспорта без переработки уже созданных доменных сущностей.
- Репозитории скрыты за интерфейсами, поэтому нынешнюю реализацию можно заменить другой.

### Liskov Substitution Principle

- Фасады зависят от интерфейсов репозиториев:
  - `IBankAccountRepository`
  - `ICategoryRepository`
  - `IOperationRepository`
- Любая реализация этих интерфейсов может быть подставлена вместо текущей.

### Interface Segregation Principle

- Репозитории разделены по сущностям.
- Каждый интерфейс содержит только операции, относящиеся к своей модели.

### Dependency Inversion Principle

- Фасады зависят от абстракций репозиториев, а не от конкретных классов.
- Конкретные реализации подключаются через DI-контейнер.

## Где применены идеи GRASP

### High Cohesion

- Модели, фабрики, репозитории и фасады имеют четко разделенные обязанности.
- Логика создания операции и изменения баланса сосредоточена в `OperationFacade` и доменных сущностях.

### Low Coupling

- Доменные сущности не зависят от репозиториев и DI.
- Связи между слоями строятся через интерфейсы и внедрение зависимостей.

## Какие паттерны применены

### Factory

Реализованы:

- `BankAccountFactory`
- `CategoryFactory`
- `OperationFactory`

Фабрики используются для:

- генерации `Id`
- создания доменных сущностей в одном месте
- инкапсуляции логики создания

`OperationFactory` дополнительно проверяет согласованность `OperationType` и `CategoryType`.

### Facade

Реализованы:

- `BankAccountFacade`
- `CategoryFacade`
- `OperationFacade`

Фасады предоставляют удобную точку входа для пользовательских сценариев и скрывают работу с фабриками и репозиториями.

### Dependency Injection

В проекте используется `Microsoft.Extensions.DependencyInjection`, регистрация всех используемых зависимостей выполняется в [ServicesCollection.cs](./Infrastructure/DependencyInjection/ServicesCollection.cs).

## Запуск приложения

Из корня репозитория:

```powershell
dotnet run --project .\src\FinancialAccountingApp\FinancialAccountingApp.csproj
```

При запуске могут отображаться предупреждения nullable-анализа, связанные с полем `Description` в модели `Operation`.
В текущей реализации это не приводит к ошибке выполнения, потому что `null` обрабатывается внутри `private setter` свойства `Description` и заменяется на пустую строку.
